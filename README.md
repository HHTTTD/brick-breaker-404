# 404 Brick Breaker — minimal

หน้า 404 ที่เลข **404** คือกำแพงอิฐ **170 ก้อน** คลิกเมาส์เพื่อปล่อยลูกบอล
ไม่มีปุ่มเริ่ม ไม่มีหน้าต่างเด้ง ไม่มีหน้าจอ game over

ไฟล์เดียวจบ ~17 KB ไม่มี build ไม่มี dependency ไม่ใช้ localStorage

```
404.html
README.md
```

## พฤติกรรม

| เหตุการณ์ | เกิดอะไรขึ้น |
|---|---|
| โหลดหน้า | เลข 404 แสดงเป็นตัวอักษรก่อน แล้วสลับเป็นอิฐ ลูกบอลรออยู่บนไม้ |
| **คลิกเมาส์ / แตะจอ / `Space`** | ปล่อยลูกบอล (ข้อความ Click to launch จะหายไป) |
| เลื่อนเมาส์ / ลากนิ้ว / `←` `→` | ไม้เลื่อนตาม รับอินพุตทั้งหน้า ไม่ต้องเล็งที่ canvas |
| ทำลายอิฐหมด | ตั้งกำแพงใหม่ +200 คะแนน ความเร็วที่สะสมไว้ไม่หาย |
| บอลตกครบทุกลูก | เสียหนึ่งจุด ความเร็วลด 15% แล้วรอคลิกใหม่ |
| จุดหมด | คะแนนกลับเป็น 0 ความเร็วกลับตั้งต้น กำแพงตั้งใหม่ ไม่มีหน้าจอคั่น |
| สลับแท็บ | เกมหยุดเอง กลับมาแล้วเล่นต่อ |

## ไอเทม

อิฐแต่ละก้อนมีโอกาส 5.5% ที่จะปล่อยไอเทมลงมา (เฉลี่ยราว 9 ชิ้นต่อกำแพง)
เป็นสี่เหลี่ยมสีส้มเล็ก ๆ ตกลงมา รับด้วยไม้ ได้ +25 คะแนนทุกชิ้น

| ไอคอน | ผล | ระยะเวลา |
|---|---|---|
| แท่งขวาง | **Wide** — ไม้ยาวขึ้น 50% | 12 วินาที |
| จุดสามจุด | **Multi** — แตกเป็นสามลูก (เพดาน 6 ลูกพร้อมกัน) | จนกว่าจะตก |
| หน้าปัดนาฬิกา | **Slow** — บอลช้าลง 30% (มีเส้นส้มใต้ไม้บอกสถานะ) | 10 วินาที |

ลูกบอลเร็วขึ้นทีละ 0.5% ทุกครั้งที่โดนไม้ เพดาน 1.8 เท่าของความเร็วตั้งต้น
ตัวคูณนี้สะสมข้ามกำแพง ลดลง 15% เมื่อเสียลูก และรีเซ็ตเมื่อจุดหมด

## สิ่งที่ยังทำงานแม้ไม่เล่นเกม

- เลข `404` ในช่องกำแพงเป็น **ข้อความจริง** ถ้า JS ไม่ทำงาน หน้าเว็บก็ยังเหมือนดีไซน์ต้นแบบเป๊ะ
- `<h1>` มีข้อความ "404 — Page not found" สำหรับ screen reader (canvas เป็น `aria-hidden`)
- ปุ่ม **Go back home** เป็น `<a>` จริง กด Tab ถึง มี focus ring และคลิกโดนปุ่มจะไม่ไปยิงบอล
- `prefers-reduced-motion` ปิดหางลูกบอลและเอฟเฟกต์อิฐแตกให้อัตโนมัติ
- บนอุปกรณ์สัมผัส ข้อความเปลี่ยนเป็น "Tap to launch" เอง

## มือถือ

รองรับครบทั้งแนวตั้งและแนวนอน ทดสอบเลย์เอาต์ด้วยการคำนวณจริงบน iPhone SE / 15, Pixel 8,
Galaxy Fold (จอปิด), iPad mini และรันตัวเกมที่ความละเอียดเหล่านั้นจริง

- **ลากนิ้วที่ไหนก็ได้บนจอ** ไม่ต้องแตะบนไม้ นิ้วจึงไม่บังไม้ (ไม้ตามแกน X อย่างเดียว)
- แตะหนึ่งครั้ง = ปล่อยลูกบอล ข้อความเปลี่ยนเป็น **Tap to launch** อัตโนมัติบนอุปกรณ์สัมผัส
- ไม้กว้างขึ้นตามสัดส่วนบนจอเล็ก (ราว 24% ของความกว้างจอ เทียบกับ 13.5% บนเดสก์ท็อป)
- ขนาดไอเทมและลูกบอลสเกลตามความกว้างจอ ไม่ใหญ่เทอะทะบนมือถือ
- **แนวนอน** มี breakpoint แยก (`max-height:560px`) ย่อกำแพงและตัวหนังสือ แล้วย้ายข้อความ hint ขึ้นด้านบน
  ไม่งั้นเนื้อหาจะชนไม้และทับปุ่ม
- กันการเลือกข้อความ ไฮไลต์สีฟ้าตอนแตะ และเมนู long-press ไว้แล้ว
- `touch-action:pinch-zoom` — ลากนิ้วเดียวคือการเล่น แต่ยัง **ซูมสองนิ้วได้** เพื่อไม่ให้เสีย accessibility

ข้อจำกัดที่ยังเหลือ: บนจอแนวนอนที่เตี้ยมาก (ต่ำกว่า 340px) พื้นที่เล่นจะแคบจนเกมยาก
ถ้าเจอกลุ่มผู้ใช้แบบนี้เยอะ แนะนำให้ซ่อนกำแพงอิฐแล้วโชว์ `<b>404</b>` แทนที่ breakpoint นั้น

## ปรับแต่ง

### แถบซ้าย
`<div class="rail">` เป็นแค่ตัวแทนของเมนูในดีไซน์ต้นแบบ
ถ้าเว็บคุณมี header/sidebar ของตัวเองอยู่แล้ว **ลบ `.rail` ทิ้งได้เลย** เกมจะขยายเต็มจอเอง

### สี
```css
--paper:#F4F4F4;  /* พื้นหลัง */
--ink:#121212;    /* อิฐ ไม้ ตัวหนังสือ ปุ่ม */
--grey:#7C7C7C;   /* บรรทัด Oops */
--mist:#C7C7C7;   /* บรรทัดจาง + HUD */
--live:#F0421E;   /* ลูกบอล ไอเทม ข้อความ Click to launch — สีเดียวในหน้า */
```

### ตัวเลขเกม
```js
const CFG = {
  lives: 3,
  speed: 440,      // px/วินาที ที่ความสูงจอ 760px (สเกลตามจอเอง)
  speedUp: 1.005,  // ตัวคูณทุกครั้งที่โดนไม้
  maxMul: 1.8,     // เพดานความเร็ว
  maxBalls: 6,     // เพดานจำนวนบอลพร้อมกัน
  dropRate: 0.055, // โอกาสที่อิฐหนึ่งก้อนจะปล่อยไอเทม
  wideTime: 12,
  slowTime: 10
};
```

### ความละเอียดของอิฐ
`GLYPH` เป็นบิตแมป **9 × 12** ต่อหนึ่งตัวอักษร `#` คืออิฐ `.` คือช่องว่าง
รวมกริด 31 × 12 = อิฐ 170 ก้อน

อยากได้อิฐใหญ่ขึ้น (น้อยลง) หรือเล็กลง (เยอะขึ้น) ให้วาด `GLYPH` ใหม่แล้วอัปเดตสามค่านี้ให้ตรงกัน:
1. `GW` — ความกว้างของหนึ่งตัวอักษร
2. `ROWS` — จำนวนแถว
3. `aspect-ratio` ของ `.wall` ใน CSS = `COLS / ROWS` (`COLS` คำนวณเองจาก `WORD`, `GW`, `GAP`)

เปลี่ยน `WORD` เป็น `['5','0','0']` ก็ได้หน้า 500 (ต้องเพิ่ม glyph ของ `5` และแก้เลขใน `<b>404</b>` ด้วย)

ระยะห่างระหว่างก้อนคุมด้วย `inset` ในฟังก์ชัน `draw()` (ตอนนี้ 9% ของขนาดก้อน)
ตั้งเป็น 0 จะได้ 404 ทึบตัน — การชนใช้ขนาดเต็มช่องเสมอ ไม่ว่าจะวาดห่างแค่ไหน

### เปลี่ยนเป็นภาษาไทย
แก้ข้อความใน `.l1 .l2 .l3` และ `<html lang="th">`
ฟอนต์ Poppins ไม่มีไทย — ในสแตกมี `"Noto Sans Thai"` รออยู่แล้ว ถ้าจะใช้จริงให้เพิ่มลง `<link>` ของ Google Fonts

## หมายเหตุเทคนิค

- เกมทำงานในระบบพิกัด CSS pixel ตรง ๆ (จำกัด DPR ที่ 2) ไม่มีการสเกลโลกภายใน
- ตำแหน่งกำแพงอ่านจาก `getBoundingClientRect()` ของ `<div class="wall">` ใหม่ทุกครั้งที่ resize อิฐจึงทับที่เลข 404 พอดีเสมอ ถ้าย้ายบล็อกข้อความ กำแพงก็ตามไปเอง
- อิฐเก็บใน `Map` แบบกริด การตรวจการชนดูแค่ 9 ช่องรอบลูกบอล ไม่ใช่วนทั้ง 170 ก้อน จึงยังลื่นแม้มี 6 ลูกพร้อมกัน
- ลูกบอลเดินแบบ substep (ไม่เกิน 4 px ต่อก้าว) กันทะลุอิฐตอนความเร็วสูง
- มีตัวกันมุมเด้ง 0.18 เรเดียน ไม่ให้บอลเด้งขึ้น-ลงตรง ๆ จนวนไม่รู้จบ

ผ่านการทดสอบ headless ด้วย jsdom: autoplay 30,000 เฟรม, บังคับดรอปทีละชนิดครบทั้งสามแบบ, แบบปล่อยบอลตก 5,000 เฟรม (เสียลูก 10 ครั้ง รีเซ็ตครบวงจร 4 รอบ) และรันซ้ำที่ความละเอียด 375×667 / 393×852 / 852×393 / 344×882 / 1400×900 — ไม่มี runtime error, ลูกบอลไม่ออกเองก่อนคลิก และเพดาน 6 ลูกไม่หลุดในทุกความละเอียด
